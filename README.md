# نتيجة الثانوية العامة 2026 — بحث

بحث في نتيجة الثانوية العامة (النظام الحديث) — **919,396 طالب** — بالاسم أو برقم الجلوس،
مع شاشة تفاصيل وتحميل النتيجة كصورة PNG أو ملف PDF.

يوجد إصداران من نفس الواجهة:

| | التشغيل المحلي | النشر على GitHub Pages |
|---|---|---|
| المجلد | جذر المشروع | `docs/` |
| مصدر البيانات | خادم Python + SQLite | ملف SQLite ثابت يُقرأ من المتصفح |
| حجم البيانات | 160 ميجا | 89 ميجا (11 جزء) |
| الترتيب | كل النتائج مرتبة بالمجموع | أول 300 مطابقة ثم تُرتَّب بالمجموع |

---

## أولاً: التشغيل المحلي

```bash
python3 build_db.py          # مرة واحدة — يحوّل الإكسل إلى results.db
python3 server.py            # أو دبل كليك على start.command
```

يفتح المتصفح على <http://localhost:8000>. للإيقاف `Ctrl+C`.

## ثانياً: النشر على GitHub Pages

```bash
python3 build_static.py      # يبني مجلد docs/ الجاهز للنشر
```

ثم أنشئ مستودعاً على GitHub وارفع المشروع:

```bash
git add -A
git commit -m "نتيجة الثانوية العامة 2026"
git branch -M main
git remote add origin https://github.com/<اسم-المستخدم>/<اسم-المستودع>.git
git push -u origin main
```

وأخيراً من صفحة المستودع على GitHub:

**Settings → Pages → Source: Deploy from a branch → Branch: `main` / مجلد `/docs` → Save**

بعد دقيقة أو اثنتين يصبح الموقع على:
`https://<اسم-المستخدم>.github.io/<اسم-المستودع>/`

### كيف يعمل بدون خادم؟

قاعدة SQLite مقسّمة إلى أجزاء 8 ميجا. المتصفح يشغّل SQLite نفسه عبر WebAssembly
(`sql.js-httpvfs`) ويطلب **الصفحات التي يحتاجها فقط** من الملفات عبر HTTP Range،
فلا يُحمَّل الملف كاملاً — كل عملية بحث تقرأ أجزاء صغيرة فقط.
لهذا يجب أن تبقى الملفات في `docs/` كما هي، ولا يعمل الموقع بفتح `index.html` مباشرة
من القرص (يحتاج خادماً يدعم Range — و GitHub Pages يدعمه).

## البحث

- **برقم الجلوس** — مثال `2001970`
- **بالاسم** — كل الكلمات لازم تظهر في الاسم بأي ترتيب، وآخر كلمة تقبل بداية الكلمة
  (`محم` تطابق `محمد` و`محمود`)
- الهمزات والتاء المربوطة والألف المقصورة لا تؤثر:
  `أحمد` = `احمد`، `مصطفي` = `مصطفى`، `فاطمه` = `فاطمة`
- رابط مباشر لأي طالب: أضف رقم الجلوس بعد `#` مثل `.../#2001970`

## الملفات

| الملف | الوظيفة |
|---|---|
| `build_db.py` | الإكسل → `results.db` (SQLite + فهرس FTS5) |
| `build_static.py` | `results.db` → مجلد `docs/` الثابت |
| `server.py` | الخادم المحلي + `/api/search?q=...` |
| `app.js` | كل الواجهة (البحث، شاشة التفاصيل، تصدير PNG) |
| `index.html` | الصفحة المحلية — تستدعي `app.js` ثم تمرّر له مصدر البيانات |
| `docs/` | النسخة الثابتة الجاهزة للنشر |
| `start.command` | تشغيل محلي بضغطة واحدة |

`app.js` لا يعرف من أين تأتي البيانات — يستقبلها عبر `initApp(searchFn)`،
لذلك النسختان تشتركان في نفس الواجهة بلا تكرار.

## إعادة البناء من ملف إكسل جديد

  الجماعي، ولا يمكن تقييد ذلك على استضافة ثابتة. النتائج منشورة رسمياً بالفعل،
  لكن انتبه لهذه النقطة قبل النشر.
